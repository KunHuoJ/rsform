# 草稿自动保存

> `useFormDraft` 把"防丢失"做成一行声明：表单每次值变化防抖写进 `localStorage`，提交成功后草稿自动清除；重新进入发现历史草稿时 `hasDraft` 为 `true`，弹一个「恢复 / 忽略」横条。

长表单（订单、录入、审批）里，用户填到一半误关页面、断网、甚至手滑刷新，半天录入全丢——这层兜底就是 `useFormDraft` 的用途。

## 用法

在 `<Form>` 内部调用（它内部读 `useForm()`，必须在表单上下文里），传一个**业务语义稳定**的 key——同一种表单复用同一 key，刷新、重开页面都能恢复。

<Demo title="草稿自动保存 / 恢复">
    <DraftDemo />
</Demo>

```tsx title="useFormDraft 基本用法"
import * as React from 'react';
import { Form, useFormDraft } from 'rsform';

function DraftBody() {
    // key 用业务语义命名——同一种表单复用同一 key
    const draft = useFormDraft('order-edit', { debounceMs: 400 });

    return (
        <>
            {draft.hasDraft && (
                <div className="draft-banner">
                    发现未提交的草稿，是否恢复？
                    <button onClick={draft.restore}>恢复</button>
                    <button onClick={draft.dismiss}>忽略</button>
                </div>
            )}
            <Form.Field name="name" label="姓名" required>
                <Form.Input />
            </Form.Field>
            <Form.Submit preventDuplicate>提交</Form.Submit>
        </>
    );
}
```

:::tip 体验恢复
在表单里填几个字段 → 刷新本页 → 顶部出现「发现未提交的草稿」横条，点「恢复」找回。点「提交」成功后草稿会从 `localStorage` 清除。
:::

## 返回值

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hasDraft` | `boolean` | 存储里存在历史草稿（未恢复 / 未忽略）→ 渲染恢复横条 |
| `draft` | `Record \| undefined` | 草稿快照；恢复 / 忽略后变 `undefined` |
| `restore()` | `() => void` | 把草稿 `deepMerge` 进当前表单值，并隐藏横条 |
| `dismiss()` | `() => void` | 仅隐藏横条，草稿仍留在存储里 |
| `clear()` | `() => void` | 主动删除存储里的草稿 |

## 参数

```ts title="useFormDraft 签名"
useFormDraft(key: string, options?: {
    debounceMs?: number; // 防抖保存间隔，默认 500
    storage?: Storage; // 默认 window.localStorage；SSR/测试可传 mock
    clearOnSubmit?: boolean; // 提交成功后自动清草稿，默认 true
    maxAge?: number; // 草稿有效期（ms）；过期草稿读取时即被清除
});
```

## 设计要点

- **回显安全** — 草稿恢复用 `form.setValues(draft, 'deepMerge')`，不重建表单、不触发 `onFieldValueChange`。已有 effects 不会因此误清空联动字段（如 `$.clearOn` 恢复时不触发）
- **提交即清** — 默认订阅 `ON_FORM_SUBMIT_SUCCESS`，提交成功后草稿从存储清除。业务里通常「提交完跳走」，保证下次进入是干净状态
- **防抖写盘** — 复用 `$.debounce`，高频输入折叠成一次写盘；保存的是 `{v: values, t: ts}` 信封，`maxAge` 据此判定过期
- **SSR 安全** — `window` 不存在时 hook 自动降级为 no-op，不在服务端炸
- **存储隔离** — key 完全由业务控制。多实例表单各用各的 key；跨用户隔离可拼用户 id（`'order-edit-' + userId`）

## 与 effects 的关系

`useFormDraft` 不走 `effects`——它是 React hook，在组件里订阅表单生命周期事件（`ON_FORM_VALUES_CHANGE` / `ON_FORM_SUBMIT_SUCCESS`），不进 Formily 的 effects 注册流。所以它和 `effects` 里的 `$.clearOn` / `$.debounce` / `$.linkedFieldProps` 完全正交，可叠加使用。
