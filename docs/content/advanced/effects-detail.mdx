# Effects 详解

`effects` 是 rsform 处理字段联动的核心机制。你把联动逻辑声明在 `effects` 回调里，rsform 在表单创建时把它注入一个 `$` helper 包并执行一次——**注册**各类响应式监听。之后字段值变化时，对应的监听自动触发，无需手动订阅、无需在组件里写 `useEffect`。

:::tip 关键心智模型
effects 回调是**注册时机**，不是**执行时机**。回调里写的每条语句都是「当 X 发生时，做 Y」的声明；具体什么时候真跑，取决于 X 什么时候发生。
:::

按类别跳转，每节顶部都有 **TL;DR** 一句话说清「这 helper 干什么、什么时候伸手」：

- **联动类**
  - [`onFieldReact`](#onfieldreact--初始化--变化都执行的响应式联动) — 初始化 + 变化都跑
  - [`onFieldValueChange`](#onfieldvaluechange--字段值变化监听) — 只在 value 变化跑（初始化不跑）
  - [`linkedFieldProps`](#linkedfieldprops--异步派生字段状态props) — 派生 options / 显隐

  - [`validateField`](#validatefield--跨字段响应式校验) — 跨字段校验
- **按行类**

  - [`setVisible` / `setRequired` / `setEditable`](#setvisible--setrequired--seteditable--字段状态语义糖)

## 工作原理

```jsx
<Form
  effects={$ => {
    // 这里只执行一次（表单创建时），用来「注册」联动监听
    $.validateField('confirm', ['password', 'confirm'], cb);
    $.linkedFieldProps('city', ['province'], compute);
  }}
>
```

`$` 包含两类东西：

1. **rsform 糖 helper**：`linkedFieldProps` / `validateField` / `onEachRowChange` /
   `onEachRowMultiChange`，闭包绑定好了 form，调用即注册，自动随字段卸载而拆卸。
2. **原始 Formily form**：`$.form`，以及 `$.onFieldReact` / `$.onFieldValueChange`（透传
   Formily 同名 hook）。其他 Formily 生命周期 hook（`onFieldMount` / `onFormSubmit` /
   `onFormSubmitValidateFailed` / `onFormReset` / …）**不在 `$` 上**，需从 `rsform`
   导入后直接调用——它们会自动注册到当前活动 form：

   ```jsx
   import { Form, onFormSubmitValidateFailed } from 'rsform';
   effects={$ => {
     onFormSubmitValidateFailed(form => { /* 校验失败时滚动到首个错误 */ });
   }}
   ```

## `$.validateField` — 跨字段响应式校验

:::tip TL;DR
`triggers` 里任一字段值变化就重跑 `cb`,返回非空串为错误信息、空串/null 为通过。适合「密码 vs 确认密码」这类一个字段校验规则依赖另一个字段的场景。注册时也立即跑一次(初始校验)。
:::

最常见的联动校验：A 字段的校验规则依赖 B 字段的值。

### 签名

```ts
$.validateField(
  name: string,              // 要校验的字段
  triggers: string[],        // 依赖的字段名数组
  cb: (values, targetField) =>   // values 是依赖字段的当前值
    | string                 //   返回非空串 = 错误信息
    | string[]               //   返回数组 = 多条错误
    | null                   //   返回 null/'' = 通过
    | Promise<上述>           //   也支持异步（如远程校验）
): { clearEffect(): void }   // 返回句柄，可手动拆卸
```

> 也支持简写 `$.validateField(name, cb)`——`triggers` 默认 `[name]`，只在该字段自身变化时重跑。

### 触发时机

`triggers` 里**任意一个**字段值变化，`cb` 就重跑。注册时 `cb` 也会**立即跑一次**
（初始校验，不用等第一次编辑）。`cb` 拿到的 `values` 是 `{ [triggerName]: 当前值 }` 的快照。

:::warning
`name` 本身**不会**自动成为触发源——只有把它写进 `triggers` 才会在自身变化时
:::
> 重跑。例：`validateField('confirm', ['password', 'confirm'], cb)` 改 password 或
> confirm 都重跑；`validateField('confirm', ['password'], cb)` 只有改 password 才重跑。

### 示例：密码确认一致

<Demo title="两次密码必须一致">
  <EffectsDemo />
</Demo>

```tsx
import { Form } from 'rsform';

<Form
  effects={$ =>
    $.validateField('confirm', ['password', 'confirm'], ({ password, confirm }) =>
      password === confirm ? '' : '两次密码不一致',
    )
  }
>
  <Form.Field name="password" label="密码" required>
    <Form.Input.Password />
  </Form.Field>
  <Form.Field name="confirm" label="确认密码" required>
    <Form.Input.Password />
  </Form.Field>
</Form>
```

输入密码和确认密码，不一致时确认密码字段下方出现红色错误；改一致后错误自动消失。
这就是 `validateField` 的工作方式——声明依赖，依赖变就重跑校验，无需手动管理。

## `$.linkedFieldProps` — 异步派生字段状态/props

:::tip TL;DR
一个字段的 props(最常见是 Select 的 `options`)或状态(显隐/必填/标题)依赖其他字段值时用。`compute` 返回对象按 key 自动分流到字段 state 或 `componentProps`。支持异步(发请求拉 options),内置防 stale。
:::

当一个字段的 props（最典型是 Select 的 `options`）或状态（显隐、标题）依赖其他字段值时用。

### 签名

```ts
$.linkedFieldProps(
  target: string,            // 要派生的字段
  deps: string[],            // 依赖的字段名
  compute: (values, targetField) =>
    | Record<string, any>            // 同步返回对象
    | Promise<Record<string, any>>   // 异步返回（如发请求拉 options）
): void
```

### `compute` 返回什么 → 赋到哪里

返回对象按 key 名分流，**用户不需要区分，返回啥就在哪儿生效**：

| 返回的 key | 赋到哪 | 举例 |
|---|---|---|
| `visible` / `display` / `hidden` | Formily 字段 state 顶层 | `{visible: false}` 隐藏字段 |
| `editable` / `required` / `title` / `value` / `dataSource` / `loading` | Formily 字段 state 顶层 | `{required: true}` 设必填 |
| 其他所有 key（`options` / `disabled` / `placeholder` / `mode` / …） | `field.componentProps` → 透传给控件 | `{options: [...]}` 喂给 Select |

`compute` 返回的对象随依赖变化重新计算。**防 stale 机制**：内部用单调计数器，如果在
你异步 compute 完成前依赖又变了，旧结果会被丢弃，只采用最新一次。

### 示例：省市级联

<Demo title="级联 Select（异步 options）">
  <CascadeDemo />
</Demo>

```tsx
import { Form } from 'rsform';

const PROVINCES = [{ label: '广东', value: 'gd' }, /* ... */];
const CITIES = { gd: [{ label: '广州', value: 'gz' }, /* ... */] };

<Form
  initialValues={{ province: '', city: '' }}
  effects={$ =>
    $.linkedFieldProps('city', ['province'], async ({ province }) => {
      if (!province) return { options: [] };
      await new Promise(r => setTimeout(r, 300)); // 模拟请求
      return { options: CITIES[province] ?? [] };
    })
  }
>
  <Form.Field name="province" label="省份" required>
    <Form.Select options={PROVINCES} />
  </Form.Field>
  <Form.Field name="city" label="城市" required>
    <Form.Select />
  </Form.Field>
</Form>
```

切换省份 → 城市的 `options` 重新派生（`{options}` 走 `componentProps` 透传给 Select）。
整个过程没有 `useEffect` / `useState`，联动逻辑全部声明在 `effects` 里。

### 示例：根据复选框显隐字段

```jsx
effects={$ => {
  // 勾选「启用」才显示 detail 字段
  $.linkedFieldProps('detail', ['enabled'], ({enabled}) => ({
    visible: enabled === true,   // Formily 顶层 state → 字段显隐
  }));
}}
```

### 与 `validateField` 的区别

| | `validateField` | `linkedFieldProps` |
|---|---|---|
| 目的 | 校验 | 派生 props |
| 回调返回 | 错误信息或空 | props 增量对象 |
| 是否异步 | 否 | 是（可发请求） |
| 防 stale | — | 有（单调计数器） |

## `$.onFieldReact` — 初始化 + 变化都执行的响应式联动

:::tip TL;DR
字段 init 时立即跑一次 `cb`,之后字段任一 observable(value/visible/...)变化再跑。适合「一个字段值驱动另一个字段显隐/props,且初始值也要生效」的场景。要初始化也生效用它;只要变化触发用 `onFieldValueChange`。
:::

Formily v2 原生 hook，rsform 挂在 `$` 上。底层是 `onFieldInit` + `autorun`——字段 init
时 `autorun` **立即跑一次** cb，之后字段任一 observable（value/visible/display/…）变化再跑。
**这是「初始化 + 变化都执行」的联动**，适合「一个字段值驱动另一个字段显隐/props，且初始值也要生效」。

### 签名

```ts
$.onFieldReact(
  pattern: string,
  cb: (field: DataField, form: Form) => void
): void
```

`cb` 收到 `(field, form)`，用 `field.value` 读当前值，用 `$.form.setFieldState` 改其它字段。

```jsx
effects={$ => {
  $.onFieldReact('requireType', (field) => {
    $.form.setFieldState('suitName', (s) => {
      s.visible = field.value === 1;
    });
  });
}}
```

> `onFieldReact` 追踪字段**所有** observable，不只是 value——所以 value/visible/display
> 变化都会重跑。适合「值驱动显隐 / 联动 props」场景。

### 与 `$.onFieldValueChange` 的区别

| | `$.onFieldReact` | `$.onFieldValueChange` |
|---|---|---|
| 初始化执行 | ✅ 跑一次 | ❌ 不跑 |
| 变化触发 | ✅（追踪所有 observable） | ✅（只在 value 变化时） |
| 典型用途 | 值驱动显隐 / 联动 props（初始也要生效） | 只在值变化时做联动（初始化不要） |

> 口诀：**要初始化也生效 → `onFieldReact`；只要变化触发 → `onFieldValueChange`**。

## `$.onFieldValueChange` — 字段值变化监听

:::tip TL;DR
字段 **value 变化时**才跑 `cb`,**初始化不跑**——这是它的核心特征(回显安全:mount 时不会误触发联动)。适合「只关心用户改了值,初始化不要动」的自定义联动(设值/改显隐)。要初始化也生效用 `onFieldReact`。
:::

Formily v2 原生 hook，rsform 直接透传。比糖 helper 更底层，适合自定义联动逻辑
（设置其他字段值、改字段可见性等）。

### 签名

```ts
$.onFieldValueChange(
  pattern: string,
  cb: (field: DataField, form: Form) => void,
): void
```

### 触发时机

| 时机 | 是否触发 |
|---|---|
| 字段 init / mount | ❌ 不跑(回显安全) |
| 字段 value 变化 | ✅ 跑 |
| 字段 visible/display 变化 | ❌ 不跑(只追踪 value) |

「初始化不触发」是它的核心特征——回显场景(从后端拉初始值填充表单)下,mount 时不会误触发联动清空/重算。这也正是 `$.clearOn` 选它作底层的原因。

```jsx
effects={$ => {
  $.onFieldValueChange('country', field => {
    // 选了中国，手机号加 +86 前缀
    if (field.value === 'cn') {
      $.form.setFieldState('phone', s => { s.value = '+86'; });
    }
  });
}}
```

## `$.onEachRowChange` — 数组按行单 key 联动

:::tip TL;DR
数组字段(Table / ArrayItems)每行的某个 key 变化时,基于该行其他 key 做联动。`pre` 是数组字段名,`key` 是监听的 key。`setFieldState(key, {value})` 派生值进 `form.values` 叶子(只读派生列也能提交)。多 key 用 `onEachRowMultiChange`。
:::

当数组字段（Table / ArrayItems）里**每一行的某个 key 变化时**，基于该行其他 key
做联动。`pre` 是数组字段名，`key` 是监听的 key。

### 签名

```ts
$.onEachRowChange(
  pre: string,               // 数组字段名，如 'rows'
  key: string,               // 监听的 key，如 'qty'
  cb: (ctx: {
    index: number,           // 行号（绝对索引）
    field: DataField,        // 变化的字段模型
    setFieldState: (key, partial) => void,  // 改该行其他 key 的状态
  }) => void
): void
```

### 示例：数量变化自动算金额

```jsx
effects={$ => {
  // 监听每行的 qty 或 price，任一变化重算 total = qty * price
  // （onEachRowMultiChange 更适合多 key，这里演示单 key）
  $.onEachRowChange('rows', 'qty', ({index, setFieldState}) => {
    const row = $.form.getValuesIn(`rows.${index}`);
    setFieldState('total', {value: (row.qty ?? 0) * (row.price ?? 0)});
  });
}}
```

`setFieldState('total', {value})` 只改**当前行**的 `total`，不会波及其他行。

#### `setFieldState(key, partial)` 能传什么

`partial` 是一个部分对象，按 key 分流到两条路径：

| 传的 key | 走哪 | 语义 |
|---|---|---|
| `value` | `form.setValuesIn` 写 `pre.index.key` 叶子 | 直接写 `form.values` 的叶子。**即使该 key 没渲染对应字段**（如 Table 的只读派生列 `total`），值也持久存在、提交时能拿到。这是派生值最常用的。 |
| `visible` / `display` / `hidden` | `form.setFieldState` | 控制该行该 key 字段的显隐 |
| `required` / `title` / `description` | `form.setFieldState` | 改必填、标题、描述 |
| `editable` / `readEmpty` | `form.setFieldState` | 改可编辑性、空值占位 |
| `rules` / `validator` | `form.setFieldState` | 动态换校验规则 |
| 其他 Formily 字段状态键 | `form.setFieldState` | `Object.assign(state, rest)` 整体合并 |

简言之：**`value` 单独走持久写入（进 form.values），其余任意 Formily 字段状态键走 `form.setFieldState` 改字段模型**。一条调用可同时传多个键：

```jsx
setFieldState('total', { value: qty * price });                 // 只派生值
setFieldState('discount', { visible: hasDiscount, required: hasDiscount }); // 改显隐 + 必填
```

> **初始触发**：每行挂载时 `cb` 也会跑一次（不只等第一次变化），所以派生值在初始就有，
> 不用手动播种。

## `$.onEachRowMultiChange` — 数组按行多 key 联动

:::tip TL;DR
`onEachRowChange` 的多 key 版本——监听一行里多个 key,任一变化触发,`cb` 拿到所有监听 key 的值。比写多个 `onEachRowChange` 省,一次注册多 key 任一变化都触发。
:::

`onEachRowChange` 的多 key 版本：监听一行里多个 key，任一变化触发，cb 拿到所有监听
key 的值，并知道是哪个 key 触发的。

### 签名

```ts
$.onEachRowMultiChange(
  pre: string,
  keys: string[],
  cb: (ctx: {
    index: number,
    fields: Record<string, Field>,    // 各 key 的字段模型
    values: Record<string, any>,       // 各 key 的当前值
    triggerKey: string,                // 这次是哪个 key 触发的
    triggerField: DataField,
    setFieldState: (key, partial) => void,
  }) => void
): void
```

### 示例：qty 或 price 变化都重算 total

```jsx
effects={$ => {
  $.onEachRowMultiChange('rows', ['qty', 'price'], ({index, values, setFieldState}) => {
    const total = (values.qty ?? 0) * (values.price ?? 0);
    setFieldState('total', {value: total});
  });
}}
```

比写两个 `onEachRowChange` 更省——一次注册，多 key 任一变化都触发。`setFieldState` 的
`partial` 分流、`value` 持久语义与初始触发同 `onEachRowChange`（见上表）。

## `$.setRefState` / `$.getRefState` — 非响应式草稿区

:::tip TL;DR
effect 间共享状态但**不触发任何重渲染**(区别于 form 字段值——改字段值会引发响应式更新)。基于 immer,传函数即草稿更新。适合「记录上一次值做去抖/去重判断」这类不需要 UI 反应的内部记账。
:::

### 签名

```ts
$.setRefState(key: string, value: any | (draft: any) => void): void;
$.getRefState(key: string): any;
```

`setRefState` 传值直接替换,传函数则用 immer 草稿式更新。读写**不进响应式追踪**,不会触发任何字段/组件重渲染——这是它和 `form.setValuesIn` 的本质区别(后者改值会触发监听该叶子的重渲染)。

```jsx
effects={$ => {
  // 记录上一次的省份，城市没变就不重新请求
  $.onFieldValueChange('province', field => {
    const last = $.getRefState('lastProvince');
    if (last !== field.value) {
      $.setRefState('lastProvince', field.value);
      // ... 重新派生城市 options
    }
  });
}}
```

## `$.clearOn` — 级联清空（回显安全）

:::tip TL;DR
依赖字段变化时清空目标字段。底层是 `onFieldValueChange`,**初始化不触发**——回显(从后端拉值填充)时不会误清空已回显的值。一行声明多依赖 → 多目标清空,省去手写 `onFieldValueChange` + `setValuesIn` 样板。
:::

级联清空是最高频组合操作：选了省份 → 清空城市，切了分类 → 清空子分类。
`clearOn` 把它一行化，且**初始 / 回显不触发**（底层是 `onFieldValueChange`，
不会在 mount 时误清回显值）。

### 签名

```ts
$.clearOn(
  deps: string | string[],      // 依赖字段：这些变 → 触发清空
  targets: string | string[],   // 被清空的字段
  clearValue?: any,             // 写入的空值，默认 undefined（Select 传 '' 更常见）
): void
```

### 示例：省市级联清空

```jsx
effects={$ => {
  // 省份变 → 派生城市 options
  $.linkedFieldProps('city', ['province'], async ({ province }) => ({
    options: await fetchCity(province),
  }));
  // 省份变 → 清空城市（回显时不会误清）
  $.clearOn('province', 'city', '');
}}
```

> 对比手写 `$.onFieldValueChange('province', () => $.form.setValuesIn('city', ''))`：
> 语义一致，但 `clearOn` 把「初始不触发」这个坑封装进去了，且一行声明多个依赖 / 多个目标。

## `$.debounce` — 联动防抖

:::tip TL;DR
高频触发先折叠,只在停顿后跑一次(用最新参数),trailing-edge。纯工具(不依赖 Formily),返回函数**跨渲染稳定**,可直接当 prop 传,无需 `useCallback`。用于远程搜索 / 输入联想 / 按输入触发远程校验。
:::

远程搜索、输入联想、按输入触发远程校验都要防抖——高频触发先折叠，只在停顿后跑一次。
`debounce` 是纯工具（不依赖 Formily），返回的函数**跨渲染稳定**，可直接当 prop 传，
无需 `useCallback`。

### 签名

```ts
$.debounce(
  fn: (...args) => void | Promise<void>,
  ms: number,
): (...args) => void       // trailing-edge：最后一次调用后 ms 才跑，用最新参数
```

### 示例：远程搜索 Select

```jsx
effects={$ => {
  const search = $.debounce(async (kw: string) => {
    const list = await api.searchUser(kw);
    $.form.setFieldState('userId', s => {
      s.componentProps = { ...s.componentProps, options: list, loading: false };
    });
  }, 300);
  // 透传给 Select 的 onSearch
  $.form.setFieldState('userId', s => {
    s.componentProps = { ...s.componentProps, onSearch: search, loading: true };
  });
}}
```

连续输入 `a` → `ab` → `abc`：前两次被丢弃，只在停顿后用 `'abc'` 发一次请求。

### 示例：远程搜索 Select

<Demo title="远程搜索（防抖 + onSearch）">
  <RemoteSearchDemo />
</Demo>

```tsx
import { Form } from 'rsform';

// 模拟远程接口
function searchUser(kw: string): Promise<Option[]> {
  return fetch('/api/users?q=' + kw).then(r => r.json());
}


<Form initialValues={{ userId: '' }} effects={$ => {
  // 防抖搜索：停顿 300ms 后用最新关键词发请求，把结果灌进 options
  const search = $.debounce(async (kw: string) => {
    const options = await searchUser(kw);
    $.form.setFieldState('userId', s => {
      s.componentProps = { ...s.componentProps, options, loading: false };
    });
  }, 300);
  // 透传给 Select：onSearch 触发搜索，关掉本地过滤
  $.form.setFieldState('userId', s => {
    s.componentProps = { showSearch: true, filterOption: false, onSearch: search, options: [] };
  });
  // 进入页面先拉一次全量
  search('');
}}>
  <Form.Field name="userId" label="用户" required>
    <Form.Select placeholder="输入姓名或拼音搜索" style={{ width: 280 }} />
  </Form.Field>
</Form>
```

输入姓名/拼音搜索：每次输入触发 `onSearch`，`$.debounce` 折叠高频输入，停顿 300ms 后才发一次请求，结果灌进 `options`、关掉 `loading`。整段没有 `useState` / `useEffect` / 手动清 timer——防抖与状态全在 `effects` 里声明。

## `$.setVisible` / `$.setRequired` / `$.setEditable` — 字段状态语义糖

:::tip TL;DR
`form.setFieldState(name, s => { s.x = v })` 写多了啰嗦,这三个糖分别直接对应最常改的字段状态键 `visible` / `required` / `editable`。**何时用糖**:只改单个状态键、想写得直白。**何时用 `setFieldState`**:一次改多个键(`{visible, required, title}`)或改非这三个的键(`title`/`dataSource`/`rules`)。
:::

```ts
$.setVisible(name: string, visible: boolean): void;     // s.visible = v
$.setRequired(name: string, required: boolean): void;   // s.required = v
$.setEditable(name: string, editable: boolean): void;   // s.editable = v
```

### 示例

```jsx
effects={$ => {
  // 勾选「启用」才显示 detail 字段 + 设必填
  $.onFieldValueChange('enabled', (field) => {
    $.setVisible('detail', field.value === true);
    $.setRequired('detail', field.value === true);
  });
}}
```

比 `$.form.setFieldState('detail', s => { s.visible = ...; s.required = ...; })` 更直白，对不熟 Formily 的团队成员也一目了然。

## `$` helper 全集

| helper | 触发时机 | 典型用途 |
|---|---|---|
| `$.validateField` | 依赖字段值变化（注册时也跑一次） | 跨字段校验 |
| `$.linkedFieldProps` | 依赖字段值变化 | 派生 options/disabled（进 componentProps）、visible/required（进字段 state） |
| `$.onFieldReact` | 字段 init 跑一次 + 任一 observable 变化 | 值驱动显隐/联动 props（**初始也生效**） |
| `$.onFieldValueChange` | 字段 value 变化（**初始化不跑**） | 自定义联动（设值/显隐），只关心变化 |
| `$.onEachRowChange` | 数组行内单 key 变化 | 按行联动 |
| `$.onEachRowMultiChange` | 数组行内多 key 任一变化 | 按行多 key 联动 |
| `$.clearOn` | 依赖字段值变化（**初始化不跑**） | 级联清空（回显安全） |
| `$.debounce` | 主动调用（trailing-edge） | 联动防抖（远程搜索 / 输入联想） |
| `$.setVisible` / `$.setRequired` / `$.setEditable` | 主动调用 | 改字段 visible/required/editable（`setFieldState` 语义糖） |
| `$.setRefState` / `$.getRefState` | 主动调用 | effect 间共享非响应状态 |
| `$.form` | — | 原始 Formily form 实例 |

> 上表是 `$` 上挂载的 helper。Formily 原生生命周期 hook（`onFieldMount` /
> `onFormSubmit` / `onFormSubmitValidateFailed` / `onFormReset` / `onFormValuesChange` /
> …）从 `rsform` 命名导入后直接在 `effects` 里调用即可，自动注册到当前 form。完整列表
> 见 [API 参考](/advanced/api) 的 effects 导出。

### effects 可以是数组

传数组会按顺序扇出执行，等于把多个 effect 函数合并：

```jsx
<Form effects={[effectA, effectB, effectC]}>...</Form>
```
